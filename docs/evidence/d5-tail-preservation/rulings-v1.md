## R1 — Clause 53: generation-fenced REFUSED uses clause 6's algebra, with a stable proof

## R2 — Clause 5: the operation list gains `attempt.ticket`
`attempt.ticket(P, agent, incarnation) -> AdmissionTicket{resolve_generation, incarnation, P, agent}` is a STATELESS sample of the session fence: MC writes nothing, records no issuance, keeps no ticket ledger, and there is no orphan or idempotency concept on the MC side. A ticket grants no custody; it is the pair of values the seal CAS will later compare against current state. Unused or lost replies are discardable. Exactly ONE ticket per gateway attempt reaches prepare: the gateway binds its locally chosen ticket to the durable attempt record by local CAS BEFORE dispatching prepare, and never rebinds; a stale ticket that does reach prepare/seal fails the generation or incarnation comparison. After a restart the gateway resolves P's fence (attempt.resolve with attempt_id none) before admitting anything, so no old ticket is ever used unknowingly. AdmissionTicket carries no ticket_id or issuance identity (the consolidated draft's AdmissionTicket type is amended to {resolve_generation, incarnation, P, agent} only). Two crash states are distinct on the gateway: a crash with NO chosen ticket bound means no remote prepare and no custody exist (the durable attempt id and ingress-ownership record may already exist — they are written before sampling — but nothing was dispatched; a fresh attempt may start after the restart fence check); a crash with a chosen ticket BOUND — whether immediately before network dispatch or after it — is treated as possibly dispatched: the bound ticket IS the conservative may-have-dispatched marker, the attempt is resolved through attempt.resolve after restart and never re-prepared, and never-sent is never inferred from a missing completion. Read-only on the fence (no bump); the gateway persists the ticket in its durable attempt record BEFORE dispatching prepare; prepare and the seal CAS both check `ticket.resolve_generation == current` and `ticket.incarnation == current`. `attempt.resolve` additionally serves the restart read (clauses 10/16): called with `attempt_id: none` it returns `{attempt_outcome: none, p_fence, fence_generation}` without writing anything — absence of a local attempt row is never treated as refusal.

## R11 — Transport binding and authority for the D5 operations (FINAL, from SUBC's source verification of the pinned daemon d95a6d62 and current)
Target: a dedicated `RouteTarget::InternalService{module_id: "magic-context", service_id: "mc.lineage"}` served by the ck-mc module — not the module's `ManagementSurface`, whose bind must stay open to its existing callers (session.status/wrapup/delete, doctor, dashboard); the authority restriction applies to this one route only. Authority: the route's decision-only `on_bind` admits iff `req.principal == Some(Principal::Reserved{module_id: "thalamus"})` — the daemon-stamped spawn-nonce principal; `BindIdentity` is untrusted and never consulted. Never exposed through the MCP tool facade; no generic wire change, no protocol pin bump. Framing: unary `Vec<u8>` request/response frames whose bodies are JSON (JSON flag state; `FLAG_BINARY` exists in the daemon and is NOT set for these calls); the daemon's hard bound is a 64 MiB serialized body per frame; there is NO streamed-request API (response streaming only). Two distinct size units: `raw_chunk_bytes` (the un-encoded source bytes in one `put`, ≤ 1 MiB) and `serialized_body_bytes` (the JSON frame body, ≤ 64 MiB; a 1 MiB raw chunk serializes to ≈1.33 MiB of base64 JSON, which is within bound — the 1 MiB rule applies to raw chunk bytes only and never recursively to the `put` frame). Inline-vs-reference decision applies ONLY to `prepare`: `prepare.source_segment` is a tagged union `{kind: "inline", segment: SourceSegment} | {kind: "ref", upload: UploadRef}`; the gateway MUST use `inline` when the serialized prepare body would be ≤ 1 MiB and `ref` otherwise. Chunk operations with typed returns: `lineage.begin{attempt: AttemptKey, ticket: AdmissionTicket, kind: "source_segment", total_bytes, total_chunks, digest: Digest} -> {upload_id: UploadId}`; `lineage.put{upload_id, seq: ChunkSeq, bytes: base64} -> {seq, chunk_digest: Digest}`; `lineage.finish{upload_id, digest: Digest} -> {upload: UploadRef}` where `UploadRef = {upload_id: UploadId, digest: Digest, total_bytes}` and `digest` is SHA-256 over the ordered raw bytes. A digest mismatch at `finish` refuses with `upload_digest_mismatch` and discards ONLY unreferenced staging data: a later `finish` with a wrong digest for an upload already referenced by SEALED or REDEEMED custody refuses without deleting anything. A `begin` whose (AttemptKey, ticket, kind, digest) key already exists but whose `total_bytes` or `total_chunks` differ refuses with `upload_declaration_conflict` and never rewrites the original declaration. The named byte quota is an aggregate over every upload and retry of the attempt, with each accepted (upload_id, seq) counted once. Uploads count against D and the named quotas below. Response bodies are ordinary JSON carrying the TYPED outcomes (SEALED/REFUSED/REDEEMED/RELEASED with their full payloads); the legacy `ErrorBody{code, message}` shape is used only for transport/authority failures and never flattens a typed outcome into a string. Upload semantics (testable protocol completion): `begin` is idempotent on (AttemptKey, ticket, kind, digest) — a retry after a lost reply returns the same upload_id; `put` with the same (upload_id, seq) and identical bytes is idempotent, different bytes for an existing seq is refused (`chunk_conflict`); `finish` is replay-stable (a second finish returns the same upload_ref); uploads are bound to their attempt+ticket and become unusable the moment the ticket is invalidated (chunks for an invalidated ticket can never be finished or referenced); an unfinished upload expires with its attempt's terminal outcome or the session incarnation advance, never by clock alone; upload bytes referenced by a SEALED or REDEEMED receipt are custody and are never deleted by GC or on a later digest mismatch of a different upload. Quotas are named numeric policy owned by MC config: `lineage.upload.max_concurrent_per_attempt = 2`, `lineage.upload.max_bytes_per_attempt = 48 MiB` (raw), `lineage.upload.max_chunk_bytes = 1 MiB` (raw). `kind` is restricted to `source_segment` — the ONLY payload the gateway has authority over (native blocks by provenance); MC's preservation manifest is MC-generated and is returned, never uploaded, so `kind: manifest` is removed. Framing: JSON bodies use JSON framing; FLAG_BINARY exists in the daemon but is NOT set for these calls. Pins: non-thalamus principal bind refused; ManagementSurface callers unaffected (source fence on its route table); a 1.5 MiB SourceSegment round-trips byte-identical through begin/put/finish; begin retry after lost reply → same upload_id; duplicate put idempotent / differing bytes refused; finish replay-stable; same-upload corrupt finish after SEALED refuses and custody bytes survive; conflicting begin re-declaration refused with the original intact; chunks of an invalidated ticket unusable; a chunked upload exceeding quota or D refuses before seal; SEALED-referenced upload bytes survive GC and a foreign mismatch; typed outcomes never appear in ErrorBody.

## R12 — D is the prepare execution budget; late seals are valid custody
D = 120 s bounds how long the gateway waits for a `prepare` to return before answering 503 to the compaction request. It does not bound the receipt's life. A seal that commits after the gateway's deadline is valid custody: the gateway's attempt is UNKNOWN, `attempt.resolve` returns SEALED, and no re-prepare and no ticket refresh ever happen. What the gateway may then do depends only on reply deliverability: if the compaction request is still open, it proceeds under the ordinary ordering — deliver the verified SEALED placeholder, observe the native successor, THEN redeem (S is never minted before the harness has replaced the transcript); if it has already answered 503 (or the client is gone), the SEALED receipt follows the release trigger (R13) once the never-replied proof holds. UNKNOWN never resets or extends the original deadline. Pins: seal commits at D+ε after the gateway timed out → resolve returns SEALED → release path (no reply) or redeem (request still open), never a second prepare.

## R13 — Gateway release trigger (accepted as proposed)
Release is selected when: the caller cancelled or the reply deadline expired, AND every alias of the receipt is closed (no in-flight retry), AND no alias has MAY_HAVE_REPLIED. Then the gateway atomically revokes future sends and alias registration (RELEASE_INTENT → NEVER_SEND) BEFORE calling MC `release`. If any alias is active or any MAY_HAVE_REPLIED is set → no release: resolve, redeem, or hold. `release` carries a stable operation identity (receipt_id + release_attempt_id); a retry after an unknown response repeats the same identity and MC treats it idempotently (CAS SEALED→RELEASED, or returns the existing RELEASED); release against a REDEEMED receipt returns `already_redeemed` and is never selected by the trigger. Pins: release-vs-reply, release-vs-redeem, release retry after unknown, and the refused release after redeem.

## R14 — Successor recognition is receipt-bound, not prefix-bound (2026-09-12, from the gateway review's parked round 3)

The gateway's round-3 fold proposed recognizing the native successor by requiring the stripped predecessor as a byte-identical prefix and assistant/response bytes in the replacement message. That predicate is wrong against the vendored anchor fixtures: the observed successors (ex13508, ex13615) REPLACE the predecessor, and the anchor is a USER message whose text is Claude Code's variable wrapper around our placeholder. Rule:

1. Canonical marker: the compaction response text the gateway returns for a sealed prepare is `<summary>\n` + FIXED_INNER + ` mc-d5:<receipt_id>:<nonce>` + `\n</summary>` — the marker sits INSIDE the summary tags (leading space, ASCII) as the normative emitter format; the gateway owner's 2.1.258 container capture showed text after the closing tag is also carried into the anchor, so recognition rests on the receiver rule (exactly one well-formed marker matching the scoped current SEALED receipt), never on client extraction assumptions, and SSE framing is never a carrier, where ReceiptId is a bounded lowercase 36-character UUID string and the nonce is exactly 96 bits rendered canonically as 20 characters of unpadded lowercase RFC 4648 base32 (the final character's low four bits are zero). The marker is therefore exactly 64 bytes including the leading space; the ReceiptId type is pinned to the 36-char UUID form for this reason. `recognition_token` is generated once per NEW receipt at seal and stored on the receipt; retries and coalesced aliases of the same receipt MUST return the same token; a genuinely new receipt (new F, or a later compaction in the same session) gets a new token, so a prior placeholder or a rewind can never match the current receipt.
2. Native continuation recognition: the gateway scans the direct text of the FIRST native user-role message of the candidate successor (scalar content or any text block of an array; tool_result blocks and any strings inside them are never inspected) for well-formed markers. Recognition requires exactly ONE well-formed marker; zero, duplicate, or conflicting markers are not a match. Match = that marker's token equals `recognition_token` of the CURRENT SEALED receipt for the same (P, agent, incarnation) whose gateway attempt record carries a durable MAY_HAVE_REPLIED or ack; a receipt whose attempt record says the marker was absent before SEND with MAY=false can never redeem. Wrapper byte equality, old-prefix equality and SSE/response bytes are never required or trusted; the bare placeholder constant is never sufficient.
3. `LineageEdge.continuation_identity` is the (receipt_id, recognition_token) pair, minted at seal, bound at redeem; redeem refuses `seal_material_mismatch` when the token found in the successor does not equal the receipt's.
4. The marker counts once in policy_reserve: reserve calc v3 is recomputed from the exact new placeholder text using realistic samples (a real UUID and a real 20-char base32 nonce, not repeated filler characters), with provenance, before mint; the 512 B path assumption is unchanged.
5. Recognition failure (no marker, unknown token, token of a non-SEALED receipt, duplicate or conflicting markers) never discards SEALED custody: the receipt stays SEALED, HealthD5.unrecognized_successors counts it with the last seen token prefix, nothing is forwarded raw and no S is minted.
6. Hermetic only: fixtures use the vendored anchor shapes with the token spliced into the inner text; no live probe.

## R16 — Complete redeem type and total precedence grid (2026-09-13; supersedes earlier R16 texts)

**Operation.** `redeem(P, agent, incarnation, observation: RecognitionObservation, candidate: Option<SuccessorCandidate>) -> RedeemResult`. Redeem is addressed by scope; MC resolves the receipt for `(P, agent, incarnation)` itself. The gateway never supplies a `LineageEdge`; MC mints it and returns it in `REDEEMED { receipt_id, edge, existing, fence_generation }`.

**No-candidate observation.** For `scan_source = no_candidate_block`, `scanned_identity`, `scanned_bytes_sha256`, and `scanned_kind` are none. When a first native user message exists but has no scannable scalar/text block, `scanned_role = user` and `native_user_index = 0`; those two fields are none only when no user message exists. `observed_markers` is empty and `candidate` is none in both consistent shapes. Any departure is metadata-inconsistent and reaches a typed refusal row.

**Marker validity.** A valid marker is exactly 64 bytes including the leading space: ` mc-d5:` (7 bytes), a lowercase UUID36, `:`, and a canonical 20-byte unpadded lowercase RFC 4648 base32 encoding of exactly 96 bits; the final base32 character's low four bits are zero. A scanned token beginning with `mc-d5:` is malformed when the leading space is missing, the total length differs, base32 is non-canonical or non-lowercase, or the UUID form is invalid. `token_prefix` records the scanned bytes verbatim (up to 64 bytes).

**Encoding rule.** No lineage serializer exists at this baseline, so clause 2 is pinned directly: request `{"op":"redeem",...}` is internally tagged with fields beside `op` and no `args` wrapper; response is the externally keyed `{"redeem":{"result":...}}` shape denoted by `LineageResponse = redeem {result: RedeemResult}`; nested unions are internally tagged by `kind`; this is the rule slice 2 must implement (the closest module tagged union is `crates/mc-module/src/tail_hygiene.rs:1212-1238`, while `crates/mc-module/src/lib.rs:793-863` is a struct request and supplies no contrary lineage convention).

**Independent precondition product.** The fixture owns dimension lists independently of these rows: scope is `absent | SEALED | REDEEMED`; observation is `no_candidate_block | no_marker | malformed | duplicate_valid | foreign_receipt | matching_receipt_wrong_token | single_valid_stored_marker`; delivery evidence is `ok | missing`, where missing is exactly `may_have_replied=false` and `ack=none`; metadata is `consistent | inconsistent`. Candidate is `none | continuation_mismatch | native_mismatch | other`, plus `observation_consistent` only for `SEALED` and `stored_edge_equal` only for `REDEEMED`; an absent scope classifies every present candidate as `other`. The test enumerates the scoped product and requires exactly one matching row. A row may collapse a whole dimension only by naming that dimension in its fixture `applies_regardless_of` list.

**Evaluation order.** Combined failures are decided in this fixed order: scope state, delivery evidence, metadata consistency, marker/token classification, then candidate relation. Thus absent always returns `resolved_absent`; every non-success case on `REDEEMED` returns `already_redeemed`; missing delivery evidence on `SEALED` beats inconsistent metadata and wrong-token material; inconsistent metadata then beats wrong-token material; a matching-receipt wrong token then beats candidate consistency. No evaluator fallback exists.

## R17 — CoverageProofV1 and the unit-validation derivation (2026-09-13; R17.3 supersedes R17.2 text: same invariants plus three gateway-owner controls)

**Types (clause 2).**
```text
projection_digest = { sha256:Digest,row_version:RowVersion,units:ordered list<UnitRecordV1> }
UnitRecordV1 = { unit:UnitKey,kind:compartment { compartment_sequence:integer }|reduction,coverage:{ start:Ordinal,end:Ordinal },locator:Option<{ mid:Mid,index:BlockIndex }>,sha256:Digest }
CoverageProofV1 = receipt_backed { covered:ordered list<BlockIdentity> }
                | real_compartment { covered:ordered list<BlockIdentity>,unit:UnitKey }
                | discharged { by: fold { units:ordered list<UnitKey> } | reduction { units:ordered list<UnitKey> }
                               | custody_transfer { transferee_receipt_id,edge_id,origin:{ receipt_id,predecessor_key,lineage_id,manifest_digest } } }
```
`kind` is the discriminant: `compartment{compartment_sequence}` is a real compartment's rendered unit; `reduction` is a committed reduced projection of one or more members and its `coverage` is exactly the ordinal range of the members it replaces (no compartment sequence; MC never invents one). A lineage_boundary row is never a unit (it has no rendered bytes). Ranges are never asserted on a proof; a proof cites a unit and the range comes from that unit's validated record. `mc.d5.unit-projection.v1` is unchanged (over {unit,row_version,bytes}; the 2a sentinel constants stand); the aggregate `mc.d5.projection.v1` is over {row_version, units: list<{unit,kind,coverage,bytes}>} so kind and coverage are hash-bound into the aggregate (hash-bound, not signed: no authentication mechanism exists here).

**Step 0 — unit validation (every pass, before any proof is read).** For each `UnitRecordV1` in `projection_digest.units`, in order: locator present → the gateway takes the block at (mid,index) in the returned pre-marker array, hashes its bytes under `mc.d5.unit-projection.v1` with (unit,row_version), requires equality with `sha256`; locator none → bytes are empty (a committed empty projection) and the digest must be the empty-bytes projection; a `compartment` unit with empty bytes is a mismatch. The aggregate over the list must equal `projection_digest.sha256`. VALIDATED(this pass) = the units that passed. RECORDED = records published from earlier ACCEPTED passes of this receipt (published only after the whole pass is accepted; a rejected pass publishes nothing). Consistency against RECORDED for every incoming record with a known unit key: incoming.row_version < recorded.row_version → regression mismatch; equal → coverage and kind must be identical; greater → advancement (record replaced on acceptance). RECORDED never authorizes anything by itself: **every unit a proof cites MUST be in VALIDATED(this pass)** — a unit accepted earlier but omitted from the current `projection_digest.units` and served array authorizes nothing (required negative: valid prior record, unit absent now → mismatch). A cold first fold therefore validates from current returned bytes with no prior entry (required positive); a tampered current unit with no prior entry is a required negative.

**Obligation.** The sealed manifest's member set, in manifest order. COVERED when the union of every proof's `covered` equals it exactly once, OR the list is exactly one `discharged` proof; mixing is a mismatch.

**Per-variant checks (after step 0; "cited unit" always means ∈ VALIDATED(this pass)).**
- `receipt_backed{covered}`: each member per its `members[]` entry: `frozen{served_sha256}` → present at its 21a locator with the archive digest; `projection_digest{unit,row_version,sha256}` → that unit is cited (kind reduction, coverage containing the member's ordinal, row_version and sha256 equal), and the member is present at the unit's locator when it exists, ABSENT when the locator is none (authorized reduced-member absence with the committed empty projection as evidence). Archive originals never restored.
- `real_compartment{covered,unit}`: cited unit with kind `compartment` and non-empty bytes; every covered member absent from the served array and its ordinal ∈ [coverage.start, coverage.end]. A reduction or empty unit here is a mismatch (an empty reduction cannot prove a fold).
- `discharged.fold{units}`: every unit cited, kind `compartment`, non-empty; every manifest member ordinal inside some listed unit's coverage; `folded_frontier` == max(end). The loss specimen (real end 1798, boundary 1940, obligation 1799–1939) and Thalamus case 1 (current empty-reduction unit with a covering range) and case 2 (prior recorded unit absent from the current pass) are all mismatches.
- `discharged.reduction{units}`: every unit cited, kind `reduction`; every manifest member's `members[]` entry names one of them; none frozen.
- `discharged.custody_transfer{…}`: as R17.2 — origin.{receipt_id, predecessor_key, lineage_id, manifest_digest} equal THIS receipt's record; transferee held REDEEMED with that edge, same lineage, predecessor == this receipt's successor_key; member correspondence by ManifestV1 block provenance `inherited_from{receipt_id: this receipt, origin_identity: member}`.

**Refusals.** `d5_carry` missing while outstanding → `503 d5_carry_proof_missing`. Step-0 failure, regression, any per-variant check failing, `discharged` not alone, unsupported variant tag → `503 d5_carry_proof_mismatch`; a rejected pass records nothing.

**Encoding.** Per R16 (internal `kind` on every union incl. `by`; UnitRecordV1.kind is the same convention). Aggregate preimage (R17.4, closes the 2be4674e7 conflict): mc.d5.projection.v1 over {row_version:U64BE, units:U64BE count + members {unit:text, kind:CE1 union (U32BE 0 compartment + U64BE compartment_sequence | U32BE 1 reduction), coverage:{start:U64BE,end:U64BE}, bytes:U64BE len + raw}} — generic CE1, no special text tags; a fixture encoder that emits "compartment"/"reduction" text is non-conformant and is corrected to this grammar; independently derived vectors (Python CE1 implementation, not the Rust fixture) are pinned in coverage-proof-vectors-v1.json §aggregate_preimages. Vectors: `coverage-proof-vectors-v1.json` (fixture-derived, owner-authored expectations, step 0 executed by the oracle against `served_array`; RECORDED and held receipts in `gateway_state`; accept→publish ordering as vector sequences). Required beyond R17.2's list: empty-reduction unit cited by fold/real_compartment (mismatch); prior recorded unit omitted from the current pass (mismatch); row_version regression / equal-with-different-coverage (mismatch) and greater (advancement); Thalamus's counterexamples.json cases carried verbatim as negatives with their sentinel-controlled hashing.

**Ownership.** MC populates `projection_digest.units` and `coverage_proof` (slice 3); the gateway runs step 0 and the checks from returned bytes plus its own records; slice 0 owns the vectors.
