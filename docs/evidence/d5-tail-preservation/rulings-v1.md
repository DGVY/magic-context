## R1 — Clause 53: generation-fenced REFUSED uses clause 6's algebra, with a stable proof
`AttemptOutcome::REFUSED{refusal: {reason: resolved_absent, receipt_id: none}, negative: generation_fence{incarnation, invalidated_ticket_generation, fenced_by}}` where `fenced_by = ticket.resolve_generation + 1` — the minimal generation that invalidates the ticket, fixed at the attempt's ticket and never "current". `current_resolve_generation` is REMOVED from NegativeProof (it changes with unrelated attempts and would break identical replay). A resolve of an already-invalidated ticket returns the reconstructed identical REFUSED and does NOT bump `resolve_generation` again; only a resolve against a still-valid ticket bumps. Counters: `refused_by_generation_responses` and `refused_by_generation_attempts` are distinct fields. No receipt row is written for this outcome; clause 6's "encoding open" text is closed to exactly {tombstone_row, generation_fence}.

## R2 — Clause 5: the operation list gains `attempt.ticket`
`attempt.ticket(P, agent, incarnation) -> AdmissionTicket{resolve_generation, incarnation, P, agent}` is a STATELESS sample of the session fence: MC writes nothing, records no issuance, keeps no ticket ledger, and there is no orphan or idempotency concept on the MC side. A ticket grants no custody; it is the pair of values the seal CAS will later compare against current state. Unused or lost replies are discardable. Exactly ONE ticket per gateway attempt reaches prepare: the gateway binds its locally chosen ticket to the durable attempt record by local CAS BEFORE dispatching prepare, and never rebinds; a stale ticket that does reach prepare/seal fails the generation or incarnation comparison. After a restart the gateway resolves P's fence (attempt.resolve with attempt_id none) before admitting anything, so no old ticket is ever used unknowingly. Read-only on the fence (no bump); the gateway persists the ticket in its durable attempt record BEFORE dispatching prepare; prepare and the seal CAS both check `ticket.resolve_generation == current` and `ticket.incarnation == current`. `attempt.resolve` additionally serves the restart read (clauses 10/16): called with `attempt_id: none` it returns `{attempt_outcome: none, p_fence, fence_generation}` without writing anything — absence of a local attempt row is never treated as refusal.

## R8 — Clauses 38/39: a durable observable for the persist-failure crash
Write-ahead order for the envelope record: (1) write `pending{sequence}` marker; (2) persist the envelope; (3) clear the marker; (4) send. A crash between (1) and (3) leaves the marker; recovery treats a present marker as `newer_unusable{sequence}` (tombstone the slot) — this is the durable observable that distinguishes it from an ordinary restart with a valid old envelope (no marker).
