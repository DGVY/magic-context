# D5 tail preservation — normative amendments §13–§20 (continues design-core.md; later sections override earlier text)

## 13. Normative amendments (v3.1, from Thalamus pm_aa06fec7 — folded, not editorial)

A) **SEALED P admission (replaces the "replay V" wording in §2).** After seal, P serves NO normal requests: managed turns arriving on P are queued behind the admission barrier (bounded by D) or refused 503 until REDEEMED or RELEASED. Appended source is never ignored and never replayed. The gateway's existing ban on transformed-body replay stands. I5 corrected: a request whose F differs from the SEALED receipt does NOT silently lose to the sealed one — redeem requires F match; mismatched material is refused (`seal_material_mismatch`) without deleting the archive and without discarding the new input (it stays queued/refused at admission, never dropped).

B) **Gateway durable attempt record.** Before the first reply byte, the gateway durably records `{attempt_id, P, agent, F, receipt_id, MAY_HAVE_REPLIED: false}` and flips `MAY_HAVE_REPLIED := true` (monotonic, durable) before writing the reply. Recovery keys on this record, never on finding F in a successor. RELEASE requires the gateway's proof of never-replied across ALL retries of that attempt (the record's bit false in every retry row for the attempt), not for one socket. After RELEASED, a new prepare with the SAME F is allowed and mints a NEW attempt/receipt (idempotency is scoped to non-RELEASED receipts); the archive is reused by content address.

C) **Two digest classes.** `manifest_digest` and `archive_id` are immutable and identify the sealed snapshot membership + source identities. `projection_digest{row_version}` is per-response and changes with every legitimate later reduction/tag/encoding change on the successor; per-pass validation compares the projection digest MC declares for THAT pass (with its row_version) — never the frozen carry bytes. §8 corrected: `refs.carry_digest` → `refs.projection_digest` (mutable, versioned); `archive_id` (immutable). After a newly applied drop, re-render and ctx_expand serve the reduced form; original bytes are never resurrected.

D) **Late-drop routing (any state).** A drop/command for a T target arriving at ANY time after seal is routed atomically by lineage lookup: P SEALED → recorded on the receipt; P REDEEMED → dedup by (command_id, target) and enqueue on the CURRENT successor if the target is carried there, else stamp ledger `covered` (folded) or `retired` (already reduced); P RELEASED → returned to P's own queue. No arrival is lost between copy and delivery; the route is a single store transaction keyed by the lineage table, retry-safe.

E) **Identity allocation for never-seen blocks.** MID allocation is the gateway's (its MID store); tag identity is MC's. `prepare` requires every supplied block to carry a gateway-allocated MID; MC never invents MIDs. Never-seen blocks: the gateway allocates MIDs idempotently for the attempt (same block bytes + attempt → same MID) BEFORE calling prepare, durably in its MID store keyed by attempt; MC then mints tag identities deterministically from (mid, index) under the seal — identity only, no decisions, no deferred commands bound, the summary instruction never processed as a turn. Crash recovery: gateway MID rows for an attempt persist; a repeated prepare with the same F reuses them; MC's seal is atomic so tag identities exist iff the receipt does.

F) **Geometry and freshness.** Token headroom uses the SAME estimator and reserves the scheduler uses (`usable_soft` is the scheduling denominator, not capacity): `estimate(system + tools + m0 + m1 + carry + anchor_reserve + output_reserve) ≤ usable_soft`, with an unknown estimate → refuse. Byte caps are two: the gateway ingress cap (64 MiB) and MC's subc frame/page capacity as configured for transform pages — the smaller governs; the final outbound gate still applies to every carry render. Freshness: the projection and any optional grace are computed BEFORE seal, so the seal transaction CAS-checks every input it depended on (A hash, coverage frontiers, P.state_version, pending-drop count); if an optional publisher committed meanwhile, the seal recomputes (bounded by D) or refuses — never seals a stale projection.

D calibration: Thalamus worker wi_1544da69 (current-CC native 503/delay, isolated fake provider) — results attach to the gate; D stays provisional until then. Receipt schema v1 updated per C (projection_digest{row_version}) and B (gateway attempt record referenced by attempt_id).

E-pin) **MID idempotency is positional.** The gateway's MID allocation key is `(attempt_id, predecessor P, ordered native MESSAGE position)` — a message-level identity; block index is separate and never part of the MID. Two byte-identical messages (or blocks) at different positions get distinct MIDs; a repeated prepare with the same F reuses the ordered allocation exactly. I2/I5 gain a duplicate-content regression: two identical messages in T must appear as two manifest entries with distinct MIDs on every prepare repetition and on the successor's served array.

## 14. D frozen and two post-refusal cases (v3.2, from Thalamus calibration pm_14a6176f)

**D = 120 s, server policy (frozen).** Evidence (CC 2.1.258, isolated fake provider, validated from raw request hashes and native boundaries, not worker labels): AUTO 503,503,200 recovers and the summary replaces all warm-up markers; AUTO persistent 11×503 retains all warm-ups, writes no summary/compact_boundary, and silently resumes the exact pending ordinary request with a 200; manual persistent 503 shows a compaction error and retains history; both manual and auto first responses tolerate a 120.003/120.004 s wait before a 503 and the next retry succeeds; 125 s success is tolerance evidence, not a client max. No 150 s extrapolation.

**Case A — ordinary P request immediately after a failed AUTO compaction (no user-visible error).** The gateway must classify by attempt state before forwarding: (i) prepare definitively REFUSED (receipt state REFUSED, or no attempt row exists) → transform the request normally on P (P was never fenced); (ii) attempt SEALED, or outcome UNKNOWN (e.g. the prepare call timed out) → do NOT forward raw and do NOT replay: query the attempt by (P, agent, F) (stable lookup handles a late commit), enforce the admission barrier (queue ≤ D or 503), preserving the appended input. Never lose or replay the appended request.

**Case B — client timeout at or near the seal commit is OUTCOME-UNKNOWN.** A gateway-side timeout cannot promise "nothing fenced"; only MC's REFUSED (durable) proves it. The gateway records the attempt as `outcome_unknown` and resolves it by the stable attempt lookup on its next touch of P; MC's seal transaction is atomic so the lookup returns exactly one of SEALED / REFUSED / absent (absent = never reached the seal, safe to treat as REFUSED after D has elapsed since the attempt's own start, recorded gateway-side).

Both cases and every §13 correction are Athena inputs. Evidence provenance: exact-version container, network=none; initial host runs were not OS-sandboxed and registered non-default URL handlers (documented by Thalamus); only four sanitized code/evidence files integrate; raw artifacts stay local to Thalamus.

## 15. Case B correction (v3.3, Thalamus pm_aa3598b5): absence is not proof

"absent after D → treat as REFUSED" is withdrawn. Elapsed wall time cannot rule out a delayed/queued prepare, a suspended process, or a seal transaction already in flight that commits after the caller's deadline; an expiry check before the transaction still races a long commit. The gateway retains UNKNOWN until MC provides an **authoritative absence-and-no-future-seal guarantee**:

- `attempt.resolve(P, agent, F, attempt_id)` — a durable MC operation that, in ONE store transaction, either returns the existing receipt state (SEALED / REFUSED) or, when no receipt row exists, writes a **tombstone** `REFUSED{reason: resolved_absent, attempt_id}` for that (P, agent, F, attempt_id). Any later seal transaction for the same key CAS-checks the tombstone and fails (`seal_after_tombstone`), so no seal can land after resolution. The tombstone is a receipt row in state REFUSED, retained under §7 rules (no archive to keep).
- The gateway's resolution of `outcome_unknown` is therefore: call `attempt.resolve`; SEALED → barrier/redeem path; REFUSED (real or tombstone) → P was never fenced or is now guaranteed never to be → transform normally. No read-then-admit; the write IS the read.
- MC-side: the seal transaction's CAS set gains the tombstone check; `preparing` rows are not a state the gateway can observe — only SEALED/REFUSED/absent exist to a resolver, and absent is converted to REFUSED-by-tombstone atomically.
- I13 (executable): a prepare whose seal txn is delayed past a concurrent `attempt.resolve` fails with `seal_after_tombstone` and leaves no fence; the resolve returns REFUSED; a resolve racing a seal that commits first returns SEALED (no tombstone written). Both orderings pinned with real two-connection interleaving.

§15 addenda (Thalamus pm_2e68e97a): `attempt.resolve` returns the existing state explicitly for ALL states — SEALED, REFUSED, REDEEMED (→ successor key returned; the gateway routes to it), RELEASED (→ P resumed; a new attempt with the same F is legitimate) — and writes a tombstone only when no row exists for (P, agent, F, attempt_id). Tombstone identity INCLUDES attempt_id, so a RELEASED or tombstoned attempt never blocks a later legitimate attempt with the same F. Review provenance: the running panel (ct_…c023bfb0b858) reviewed gate commit b1fd319a = v3.2; §15 (b60d6d88 = v3.3) is a subsequent normative amendment not covered by that panel and is folded into the final amendment review with the I13 interleavings before any spec mint.

## 16. Amendments from the salvaged round-0 panel reads (v3.4; ct_…c023bfb0b858 round 0, astra + grok — the panel saw the design truncated at line 109, so these are against v3.2 §1–§12 and are folded here as normative)

16.1 **Nested descent while carry is outstanding (grok #5 — a loss sequence).** A second native compaction on the successor S while its carried V-tail is still unfolded: the carry is MC-injected and NOT in Claude Code's native transcript, so the gateway's source segment for prepare(S, …) will not contain it and F' cannot cover it. Rule: prepare on any key whose receipt lineage has an outstanding carry (`source_frontier > folded_frontier`) MUST include the outstanding carried range as part of T for the new attempt, sourced from S's own archive (not from the gateway segment); the new archive is the union {inherited carry, S's uncovered native tail}; the manifest records provenance per block (`inherited_from: receipt_id` vs `native`). Descent chains are bounded by the existing merge-collapse cap; a chain carries at most the union of its unfolded tails, and the budget (§9) is evaluated over that union. I14: seed P→S with carry outstanding, descend S→S2 with the fixed placeholder, assert every P-tail manifest block is served on S2's first pass (content probe) and expandable.

16.2 **Per-block frozen digests for unreduced carry (grok #4 / §13C tightening).** §13C's mutable `projection_digest{row_version}` governs blocks whose applied state changed after seal. For a carried block with NO new decision since seal, the per-pass validation compares the block's served bytes to the FROZEN manifest `served.sha256` — the projection for an unreduced block is required to be a pure function of (source, A) with no clock/host input, and this is pinned (I8 tightened): defer, defer, restart serve byte-identical unreduced carry; a block reduced on S after seal validates by its new unit's placeholder bytes, declared in that pass's projection_digest with the unit key. A checker never compares a reduced block against the frozen archive bytes (no false refusal), and never accepts an unreduced block whose bytes differ from the frozen digest (no admitted mutation).

16.3 **Frontier split must rebind every coverage consumer (grok #7, astra #4).** Enumerated sites that today derive coverage from the terminal compartment / last-compartment-end and must be rebound to `folded_frontier` (with `lineage_anchor` used only for continuation/ordinal rebasing): `resolve_coverage` coverage_end_ordinal + boundary identity; `coverage_ordinal_from_compartments`; m0 compose boundary/coverage; m1 `new_coverage`; historian trigger `max_compartment_end_ordinal`; `assemble_historian_firing` chunk_start; ctx_expand `last_compacted_ordinal` and range-mode transcript bounds; `first_uncovered_live_block` / `validate_live_boundary_ordinal`; `descend_lineage` `coverage_ordinal = placeholder`; compaction-marker scheduling to the host (`boundary_id` in committed execute responses); the gap-accepting fake_compaction test. Each is a named executable pin in the spec (I15: a table-driven test that seeds the specimen shape and asserts each consumer reports folded_frontier=1798, not 1940). The empty lineage_boundary row is retained ONLY as an anchor row flagged `episode_type='lineage_boundary'` and is excluded from coverage derivation everywhere (today `decay_render` already excludes empty-payload rows from rendering; coverage derivation must do the same, gated to lineage_boundary rows so OpenCode/Pi sparse-ordinal behavior is untouched — 16.6).

16.4 **Budget inputs are on prepare (grok #9).** `prepare` carries a `budget` struct from the gateway: `{usable_soft, output_reserve, anchor_reserve, system_tokens, tools_tokens}` for the session's current model geometry as the gateway resolves it (the same values Thalamus already sends on TransformInput), plus MC's own m0/m1 estimates. With those, the refusal is decidable at prepare on module-held inputs; an absent field → refuse `budget_unknown` (no floor-policy fallback).

16.5 **REFUSED never falls into passthrough (grok #8).** A REFUSED attempt returns to the gateway as a typed refusal; the gateway replies 503 to the compaction request and MUST NOT route the compaction request or the following ordinary request through `lineage_protocol_passthrough` or any raw-forward arm; the ordinary request is transformed normally on the unfenced P (§14 Case A). Pinned: with prepare REFUSED, the next request's served array equals a normal P transform (content probe), and the raw over-limit array is never forwarded (size assertion).

16.6 **Receipts/archives ownership and deletion (grok #10, astra #6).** Receipts and archives carry BOTH `predecessor_key` and `successor_key` (nullable until redeem) and a `lineage_id`; `session.delete(P)` while a receipt is SEALED-unredeemed refuses (`sealed_unredeemed`) unless `force`, and after REDEEMED deletes only P-owned rows — the archive's ownership transfers to S at redeem (a row-level `owner_key` updated in the redeem txn), so deleting P never removes S's sole recovery source; deleting S removes S-owned archives; `last_activity` GC skips any key with a SEALED receipt; the RELEASED 24 h sweep is by receipt, and an archive blob is deleted only when no receipt in any state references its `archive_id` (content-addressed reuse across attempts is reference-counted, never time-swept). Both receipts tables are session-scoped tables added to the deletion/orphan-sweep list. Concurrent prepares for the same (P, agent, F): the seal CAS on P.state_version serializes them; the second sees the SEALED row and returns it (idempotent), never a second archive.

16.7 **Shared-path gating (grok #11).** Every change in 16.3 is gated on the presence of a `lineage_boundary` row / a receipt for the key; keys without D5 state take the existing code path unchanged, pinned by the differential goldens for OpencodeAiSdk and Pi profiles.

## 17. Corrections to §16 (v3.5, Thalamus pm_1142173a — source-checked)

17.1 **§16.4 is replaced.** TransformInput today carries the raw body + `geometry{usable_soft, usable_hard, derivation}` only (transform.rs:67–106; wire TransformRequest subc_transform.rs:139–193; WireUsage carries current_total_input_tokens/context_limit_tokens). No output_reserve / anchor_reserve / system_tokens / tools_tokens exist on the wire, and the gateway's usage meter does not observe split system/tool counts; `max_tokens` on the SUMMARY request is not the successor's output reserve; the summary turn's tools/system may differ from a normal turn. New **budget-evidence contract** on `prepare`: (a) `geometry` as today; (b) `envelope`: the identity (request id + sha256) of the most recent *normal-turn* outbound envelope on P that the gateway retained, plus its raw system and tools byte segments (not counts) — MC runs its own estimator over those bytes and over its m0/m1 and the projected carry, with estimator provenance recorded in the receipt; (c) `reserves`: `output_reserve` as MC's configured reserve for the model (MC-side, from window-geometry), `anchor_reserve` as a fixed MC constant for the continuation wrapper (measured from the placeholder + wrapper bytes, recorded); (d) **unknown ≠ zero**: any absent envelope segment or unresolvable geometry → refuse `budget_unknown`. No numeric split counts are demanded from the gateway; diagnostic captures are not authoritative inputs.

17.2 **§16.1 premise confirmed and sharpened.** The native source segment excludes MC-injected carry by construction (controls 13615/16/17: native 4/6/8 messages vs forwarded 6/8/10; m0/m1 absent from every native message); the gateway's view of MC's outbound projection is a different surface from the next native request and is not source custody. Nested prepare rule as stated in 16.1, with three additions: the union {inherited archive, genuinely new native source} is deduplicated by **provenance/identity** (receipt_id + block identity), never by content hash; CURRENT reduction state A on S is applied when projecting inherited blocks (reusing the original archive V must never resurrect a drop applied on S after the first descent — the inherited block's projection is recomputed under S's A, and the frozen per-block digest for it is re-minted under the new seal); and the chain preserves provenance across archive collapse (the new manifest records the originating receipt for every inherited block).
