## Fixes

- **OpenCode sessions were labelled as OpenCode 2 after 0.42.4.** OpenCode 1.18.30 calls both the v1 `server()` entry and the v2 `setup()` entry on the published plugin object. `setup()` treated that as an OpenCode 2 host and locked the harness to `opencode2`, so every session-scoped row that seat wrote (tags, session metadata, project bindings, compartments, notes, and the rest) was stored under the wrong label. Dashboard subagent filtering, per-harness session delete, and doctor counts then looked at the OpenCode label and missed those rows. `setup()` is now inert unless the host actually provides an OpenCode 2 session hook, and `server()` locks `opencode` first so a wrong-order call fails at boot instead of mis-tagging.

- **Existing mislabelled rows are rewritten on first boot.** Schema version 85 relabels `opencode2` → `opencode` in every table that stores a harness. No released Magic Context has run on a real OpenCode 2 host against the shared database, so those rows are the v1 mislabel above. Where the same session already had both labels (session project bindings are the common case), the newer row is kept. The fresh-install schema is unchanged.

- **Dashboard Hide subagents now follows OpenCode's own parent pointer.** Task-spawned child sessions are hidden when `session.parent_id` is set in OpenCode's store, even if Magic Context has no metadata row for that child, and the metadata flag is honoured whether it was stored as `opencode` or `opencode2`.
